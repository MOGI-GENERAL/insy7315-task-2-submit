# Requirements traceability

Each user story (US) and non-functional requirement (NFR) is matched to the endpoints, screens and tests that deliver it.
Status is **Done**, **Partly** or **Planned**, and the note says what is missing.
Tests are in `apps/api/test` and next to the code in `apps/api/src`.
Endpoints are listed in `packages/contract/src/routes.ts`, and screens are routed in `apps/web/src/App.tsx`.

## Non-functional requirements

| Requirement                                                                       | How it is met                                                                                                                                                                                                                               | Tests                                                | Status                                                                          |
| --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------- |
| NFR01 Notify eligible recipients within a minute                                  | The API writes the inbox rows and sends push after an offer is posted, and logs how long the fan-out took                                                                                                                                   | `notifications.test.ts`                              | Partly. Measured in tests only, not on a phone                                  |
| NFR02 No core action takes more than a minute                                     | Posting, claiming and confirming a handover are each one short form                                                                                                                                                                         | none                                                 | Partly. Built for speed, not timed                                              |
| NFR03 Core screens load under 500 KB, with thumbnails by default                  | Lists load Cloudinary thumbnails and the full image appears only on the handover record. A size check in `npm run check` fails the build above 500 KB                                                                                       | `cloudinary-photo-store.test.ts`                     | Done. The recipient feed measures 485 KB against the 500 KB budget              |
| NFR04 Installable web app on an entry-level Android phone                         | A web app manifest, a service worker with an offline shell, and a responsive layout                                                                                                                                                         | none                                                 | Partly. Built and deployed. Installing it on a handset has not yet been tried   |
| NFR05 WCAG 2.2 AA                                                                 | Shared feedback kit with live regions and labelled forms. All 30 screens were checked with axe at three widths and at 200% zoom, and the results are in `docs/accessibility`. CI runs axe on every screen for every role at 360 and 1280 px | `feedback.test.ts`, `apps/web/a11y/audit.spec.ts`    | Done. Testing with a screen reader on a handset is not done                     |
| NFR06 English, Afrikaans and isiXhosa                                             | Every string and notification template exists in all three, and the language is saved to the user                                                                                                                                           | `strings.test.ts`, `templates.test.ts`               | Done. | NFR07 Keep input across a dropped connection and complete it once                 | Every state-changing request is idempotent, so a retry never duplicates a claim                                                                                                                                                             | `claims.test.ts`, `handovers.test.ts`                | Partly. | NFR08 No cold starts in the busy window                                           | The API runs on a free plan that sleeps when idle                                                                                                                                                                                           | none                                                 | Not met.
